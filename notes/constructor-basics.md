# 构造方法入门

## 这个概念解决什么问题？

构造方法（构造器）在 **`new` 对象时**被调用，用来把对象的初始状态设好（必填字段赋值、校验合法性）。  
没有合格的初始状态，后面的方法会处处出问题。

## 和普通方法差在哪

| | 构造方法 | 普通方法 |
|--|----------|----------|
| 名字 | **必须和类名完全一样** | 自己起名 |
| 返回类型 | **不写**（连 `void` 也不写） | 必须写 `void` / `int`… |
| 何时调用 | 只能 `new 类名(...)` 时 | 对象造好后随时调 |
| 作用 | 初始化 | 完成某项业务 |

## 分类

| 种类 | 写法 | 场景 |
|------|------|------|
| 无参构造 | `Person() { ... }` | 全用默认值，或稍后 setter |
| 有参构造 | `Person(String name) { ... }` | 创建时就必须带上网名、金额等 |
| 重载构造 | 多个同名、参数列表不同 | 提供多种创建方式 |
| 默认构造 | 你一个都不写时，编译器自动给无参 | 一旦手写了任意构造，默认无参就**消失** |

## 关键规则（入门必记）

1. `this.字段 = 参数`：区分「字段」和「同名参数」
2. `this(...)`：构造器里调用本类另一个构造器，且必须写在**第一行**
3. 构造里可以校验：不合法就 `throw new IllegalArgumentException(...)`
4. 构造不能是 `abstract` / `static` / `final`（入门先记住：别乱加这些）

## 使用场景

1. **订单 / 账户创建必须带金额、id** → 有参构造 + 校验（你写过的 `Order`）
2. **计数器在 new 时 +1** → 构造里调静态方法（`InstanceCounter`）
3. **多种创建入口** → 重载：`ofYuan` 风格也可放静态工厂，构造仍负责真正初始化

## 常见误用

- 给构造写了 `void`：那会变成普通方法，`new` 时不会走它
- 手写了有参构造后，还写 `new Person()`，却没再提供无参 → 编译失败
- 参数和字段同名却忘了 `this.`，等于给参数自己赋值，字段仍是默认值
